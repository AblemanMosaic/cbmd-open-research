# Governed CBMD discovery

CBMD means **Constraint-Bound Mathematical Discovery**. It is the research
method: pose a bounded mathematical possibility, state what must be preserved,
test or prove it under exact hypotheses, and retain corrections and negative
results. The governed discovery harness is a local implementation of that
workflow. It is separate from this research repository and from the arithmetic
model used by a particular evaluator.

| Layer | What it supplies | What a passing result establishes |
|---|---|---|
| CBMD method | Questions, hypotheses, obligations, revisions, and stop conditions. | The inquiry has an explicit claim boundary. |
| Governed discovery harness | Input hashes, execution intent and terminal custody, evidence ledger, adverse controls, claim ceilings, and pause state. | The recorded operation and the particular checks performed. |
| BCM-1 cost model | Declared charges for the amplitude evaluator's arithmetic. | Only the counted arithmetic and separately justified bounds. |
| Evaluator | A scalar recurrence or total joint value realization. | Value correspondence when proved; costs only where separately charged. |
| Research checkout | Selected claims, arguments, portable checks, custody records, and revisions. | The checks declared by each discovery and actually runnable here. |

The harness distinguishes the mathematical object, operation, realization,
evidence, interpretation, and claim standing. A process receives an intent
record before execution and a terminal record afterward. Missing custody,
runner failures, counterexamples, and superseded statements remain visible.
Evidence may justify a successor contract; it does not rewrite the contract
under which it was produced.

The normal sequence is to freeze one question and its exact inputs, select a
realization, retain execution evidence, check adverse cases and source
correspondence, then apply the appropriate claim ceiling. A finite exact audit
is bounded evidence. A compiled statement with proof escapes is not a proof.
A compiled proof is source-bound only when the correspondence is itself
established. Cold replay, a separate implementation, independent verification,
and specialist review are distinct observations.

The [bootstrap evidence index](../../evidence/iterations/bootstrap-2026-10/README.md)
summarizes retained local results through Cycle 17. Its newer M3 and K1 results
are not yet replayable from this checkout. In particular, local evidence for
source equality and exact BCM-1 counts does not supply total per-cell cost,
deployment, or a native SAT speedup. The
[native joint realization dossier](../../discoveries/algorithms/native-joint-realization/README.md)
states that narrower boundary.

The [integration roadmap](../../docs/INTEGRATION_ROADMAP.md) separates exact
inventory, proof staging, cold replay, a separate formula verifier, cost scope,
and a frozen public provisional snapshot. Existing discovery checks continue
to define what this repository verifies. The ECH line retains its own
geometric transport obligations.

Current standing is a public provisional research snapshot with authority

description does not start another investigation, issue a release, contact a
reviewer, establish novelty, or supply independent verification. Upload of the

requires separate authorization.
