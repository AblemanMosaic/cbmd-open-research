# Publication checklist

Complete this checklist before creating or making the repository public.

## Content

- [ ] No private correspondence, cover letters, or prospective-reviewer association.
- [ ] No credentials, access tokens, personal machine paths, or hidden history containing them.
- [ ] No unpublished third-party source text or redistribution-restricted files.
- [ ] Every discovery has an exact statement, standing, nonclaims, and smallest decisive test.
- [ ] Historical completion language is excluded or visibly superseded.
- [ ] AI assistance is disclosed.

## Rights and attribution

- [ ] Code and prose licensing are selected at the path level.
- [ ] Third-party code, data, figures, and quotations have source and license records.
- [ ] Mosaic name and logo provenance, intended use, and separate reuse boundary have been reviewed.
- [ ] Author names, affiliations, and contact channels are intentionally public.
- [ ] Intended journal or venue policies have been checked.

## Engineering

- [ ] `python -B tools/validate_repository.py` passes.
- [ ] Every included discovery's default checks pass from a clean clone.
- [ ] Generated artifacts reproduce from their declared sources.
- [ ] The candidate has been inspected at GitHub's rendered Markdown level.
- [ ] Release files and hashes are prepared outside the mutable source tree.

## Publication

- [ ] Default branch protections and required checks are configured.
- [ ] Issue forms are enabled; blank issues are intentionally allowed or disabled.
- [ ] Discussions policy is decided.
- [ ] The first release is drafted with all intended assets before immutability is enabled.
- [ ] Zenodo integration, if desired, is enabled only after the release structure is stable.
