# CBMD public-repository refactor plan

## Objective

Create a readable GitHub repository that accepts new discovery files without turning the internal CBMD archive into a public dumping ground or blurring model verification with mathematical proof.

## Phase 1 — local public candidate

Status: implemented in this directory.

- Establish the root discovery registry and stable directory grammar.
- Seed one ECH discovery with neutral public naming.
- Remove prospective-reviewer association from public surfaces.
- Add claim-state, correction, contribution, and AI-disclosure policies.
- Add structured objection forms and a repository validator.
- Keep publication and external repository effects at `NONE`.

## Phase 2 — ECH public-content audit

- Compare the neutral public dossier with the final private specialist packet.
- Decide which verification sources may be redistributed.
- Add only license-cleared, standalone checks to the public tree.
- Regenerate neutral screenshots and exact receipts.
- Review all references and statements for source accuracy.
- Confirm that personal names appear only as authors or bibliographic references, never as implied reviewers.

## Phase 3 — clean-clone qualification

- Initialize a fresh local Git repository.
- Commit the candidate and clone it to a separate directory.
- Run the repository validator, deterministic explorer build, and exact model test.
- Verify the tree contains no undeclared generated files or local paths.
- Record the commit and candidate-tree hashes in an external release receipt.

## Phase 4 — GitHub bootstrap

Requires separate explicit authorization.

- Create the external repository with the agreed owner and name.
- Push the clean qualified history only.
- Enable Issues and Discussions.
- Protect the default branch with pull requests and required checks.
- Confirm rendered README navigation and issue forms.

## Phase 5 — first provisional release

- Tag a clearly provisional version such as `ech-g2-low-sector-v0.1.0-provisional`.
- Attach the neutral standalone explorer and exact verification receipt.
- Publish the release only after all assets are attached.
- Optionally enable immutable releases and archival DOI integration.

## Phase 6 — extension

For each additional CBMD discovery, copy `templates/discovery/`, assign a permanent ID, add one registry entry, and run the validator. The architecture does not need to change merely because a discovery gains more arguments, data, programs, figures, or review records.

## Explicitly excluded from this refactor

- Publishing the internal CBMD archive.
- Claiming author, specialist, journal, or canonical approval.
- Publishing private review correspondence.
- Treating finite checks as geometric proof.
- Making the GitHub repository public, issuing a release or DOI, or sending an external announcement during the private-candidate phase.
