# Revision 0.11.0 — a verified decider for the characterization

Revision 0.9.0 proved
`TerminalStable ↔ WellFounded LiveArc ∧ LiveClosed ∧ LiveBound`. The last two
conditions are finite checks. `Decide.lean` decides the first by **peeling**:
start from every vertex and, each round, keep only the live vertices that still
have a live out-neighbour that was kept. It then assembles an executable
decider:

```lean
def decideTerminalStable (mult) (outdegree capacity) : Bool
theorem terminalStable_iff_decide (pos : ∀ u, 0 < outdegree u) :
    TerminalStable mult outdegree capacity ↔ decideTerminalStable mult outdegree capacity = true
```

| declaration | content |
|---|---|
| `peel_drop`, `peel_fix_or_count`, `core_fix` | a round that changes the set removes a vertex, so after `n` rounds the set is a fixpoint |
| `core_not_acc` | every vertex in the core is `LiveArc`-inaccessible |
| `notAcc_in_iter` | every inaccessible vertex survives every round |
| `wellFounded_iff_core_empty` | so `LiveArc` is well founded exactly when the core is empty |
| `terminalStable_iff_decide` | the decider is correct |

This is the same pattern as the conflict-free decider of
`CBMD-CON-CAPACITY-PRESERVATION-001` revision 0.15.0, and here it replaces the
census's cycle detection by a proved procedure.

## Run by Lean (`verification/reference/lean_decider_bridge.py`)

Lean evaluates `decideTerminalStable` on 500 systems drawn from the census
generator, which allows arbitrary digraphs with a reachable sink. It is
compared with `characterize.transfer_holds`, which simulates capacity-blocked
firing from every admissible state:

| quantity | value |
|---|---|
| systems | 500 |
| Lean verdict = simulated transfer | **500** |
| transfer / no transfer | 68 / 432 |
| containing a directed cycle | 451 |

The census property is transfer and the decider decides terminal stability, so
the agreement is also an empirical check of the bridge between the two
described in revision 0.9.0.
