# Revision 0.2.1 — fail-closed checked decoding

This revision changes the qualification contract, not the mathematical
statement or its evidence.

`FINITE_DYNAMICS_CHECKED_DECODING` was executable and Lean-backed, but its
`required` flag was false. A machine without Lean could therefore record that
gate as failed while the aggregate full-qualification status remained `PASS`.
That contradicted the documented full-scope contract.

The gate is now required. The dependency-free public entrypoint remains
`python -B tools/qualify_repository.py --repository-only`; the full entrypoint
now fails if the checked decoder cannot run or returns a nonzero result.

The first clean CI run then failed honestly: Lean 4.35.0 was installed, but
`PATH` selected an Elan proxy with no default toolchain after the decoder moved
its program to a temporary directory. Tool resolution now prefers the explicit
override and exact Elan 4.35.0 installation before consulting `PATH`.

No theorem, finite count, source file, or retained evidence receipt changed.
