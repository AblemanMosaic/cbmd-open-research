# Public qualification repairs before version 0.1.0

Status: repaired before publication

These failures occurred while adapting the sealed Q10 research result into a
portable public checkout. They are retained because a clean publication story
would hide useful evidence about the boundary.

1. The custody scanner initially matched the Windows-path detector contained
   in its own source. The scanner now excludes only its own implementation from
   the content scan; every other public discovery file remains covered.
2. The public replay initially contained one transcribed character error in
   the expected independent-result SHA-256. The produced output matched the
   sealed Q10 result. The constant was corrected to the sealed digest
   `9cd7fb89c0e4ccd45d40add37e91e43fb0a7dbdb95cdc60a0eea0c0c431c9d05`.
3. The Lean replay initially searched only `PATH`, while the pinned Lake binary
   on the qualification host was installed under the elan toolchain directory.
   The replay now resolves the pinned toolchain location, while retaining an
   explicit `--lake` override and a `PATH` fallback.

After these repairs, custody verification, deterministic finite replay, Lean
source audit, and the pinned Lean build all passed. These are packaging and
observability repairs only; they do not raise the mathematical claim ceiling.
