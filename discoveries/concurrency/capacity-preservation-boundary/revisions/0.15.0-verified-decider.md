# Revision 0.15.0 — a verified decision procedure for conflict-free nets

Revision 0.13.0 compiled `¬ Preserves ↔ Certificate` for conflict-free nets in
which every transition has an input place. It left one classical step to a
census bridge: that the greatest-fixpoint computation decides `Certificate`.
That step is now compiled, and the result is an executable decider with a
correctness theorem (`ConflictFreeDecide.lean`):

```lean
def decidePreserves (N : Net P T) (cap : Fin P → Nat) : Bool
theorem preserves_iff_decide (cf : IsConflictFree N) (hin : HasInput N) :
    Preserves N cap ↔ decidePreserves N cap = true
```

## How the fixpoint is closed off

`round` keeps a transition if it has an option — values range over
`Fin (cap q + 1)`, so every quantifier is finite and decidable — that ends or
leads into the current set. Starting from the full set:

| declaration | content |
|---|---|
| `count_drop` | a round that changes the set strictly lowers its count |
| `fix_or_count` | after `k` rounds the set is a fixpoint, or at least `k` transitions are gone |
| `alive_fix` | so after `T` rounds it is a fixpoint (in the second case, the empty set) |
| `closed_sub_iter` | every certificate set lies inside every round |
| `alive_closed` | the final set is itself a certificate set |
| `certificate_iff_alive` | hence `Certificate ↔ ∃ t0, floor ∧ t0 survives` |
| `preserves_iff_decide` | the decider is correct |

Axioms at most `[propext, Classical.choice, Quot.sound]`. The `Classical`
dependency comes from the characterization's proof, not from the decider,
which is computable.

Lean itself evaluates `decidePreserves` (`#eval`) on 400 random conflict-free

| nets | 400 |

## Only the threshold value matters, compiled

The first decider enumerates every value up to `cap q`, which is
pseudo-polynomial. `thr t0 t q` is the least value at which `t` overflows at `q`,
raised to `t0`'s floor. `stepP_iff_stepT` proves that one value per place
suffices: overflow is monotone in the value, and the only value-dependent
ending reason (the consumer's lower literal) prefers smaller values. Hence

```lean
theorem preserves_iff_decideFast (cf : IsConflictFree N) (hin : HasInput N) :
    Preserves N cap ↔ decidePreservesFast N cap = true
```

Read off the definition, `decidePreservesFast` makes `T` candidate choices of
`t0`, each with `T` rounds over `T` transitions and `P` places. The ending test
in each step quantifies over at most `T · P` pairs. So it uses
`O(T⁴ P²)` comparisons and additions, on numbers no larger than the inputs plus
one, independent of their magnitude. The count is read off, not formalized. Lean evaluates it instantly at `cap = 10⁶` on the two-cycle example.
The bridge runs both deciders on all 400 nets; both match brute force on every
one.

## Standing

The conflict-free polynomial side is compiled end to end: the
characterization, the fixpoint, and an executable polynomial decider proved
correct. The complexity-class *statement* (that this is polynomial in a model
of computation) is, as elsewhere in the dossier, not formalized; the operation
count is read off the definition.
