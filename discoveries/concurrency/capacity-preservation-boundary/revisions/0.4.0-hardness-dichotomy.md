# Revision 0.4.0 — the open question answered: a dichotomy at two input places

Version 0.1.0 found by census that the live-set characterization breaks as soon
as a transition has two input places, and recorded the open question as

> whether some other local capacity condition repairs the multi-input case;
> only the natural refinement is refuted

with the explicit non-claim that no impossibility was being asserted. Revision
0.3.0 then characterized the one-input case outright. This revision closes the
gap between them, and the answer is sharper than "some other condition might
work": **no polynomial-time condition of any kind can work, unless P = NP.**

| transitions have | status |
|---|---|
| at most one input place | characterized (revision 0.3.0); decidable by a greatest fixpoint in polynomial time |
| two input places | **coNP-complete** |

The boundary the census located structurally is the same boundary at which the
problem becomes intractable. That is not a coincidence, and the reason is
visible in the mechanism this dossier identified in version 0.1.0: a transition
with several input places is enabled by a *conjunction*, and conjunctions are
what make a satisfiability problem out of a reachability problem.

## Membership

Deciding `PRESERVES(N, C)` is deciding that **no** admissible marking is both
capacity-dead and ordinarily enabled. The complement is in NP: a marking is
bounded by `C` and so has polynomial size even with capacities written in
binary, and both halves of "bad" are checked in `O(PT)` arithmetic operations.
So preservation is in coNP.

## Hardness

Two ways a transition can fail to be capacity enabled:

```
t is NOT capacity enabled  <=>  some q has m(q) < pre(t,q)               ... (A)
                            or  some q has m(q) - pre(t,q) + post(t,q) > C(q)  ... (B)
```

With unit weights and capacities in `{0,1}`:

* **(A)** with `pre(t,q) = 1` says *"q is false"* — a negative literal, and an
  input place;
* **(B)** with `pre(t,q) = 0`, `post(t,q) = 1`, `C(q) = 1` says *"q is true"* —
  a positive literal, and no input place.

So one transition per clause, taking input from the places of its negative
literals and producing into the places of its positive ones, is blocked exactly
when its clause is satisfied. The number of input places of that transition is
the number of negative literals in the clause.

### Keeping every transition fed

A transition with no input place is a modelling oddity — this dossier's own
census generator excludes them — so the reduction should not lean on them. That
constrains every clause to carry at least one negative literal, and such a CNF
is always satisfied by setting everything false. The reduction therefore
targets the question the other half of "bad" actually asks:

> given a CNF in which every clause has at least one negative literal, is there
> a model that is not all-false?

The "ordinarily enabled somewhere" requirement expresses exactly that: add, for
each atom place `a`, a transition consuming from `a` and producing into a place
of capacity `0`. It is blocked at every marking, and ordinarily enabled exactly
when `a` holds a token.

That restricted problem is NP-hard. Given an arbitrary CNF over `x₁..xₙ`,
introduce complements `x̄ᵢ` and a guard `g`, and take

```
(¬xᵢ ∨ ¬x̄ᵢ)                            two negative literals
(xᵢ ∨ x̄ᵢ ∨ ¬g)                         one
(¬xᵢ ∨ g),  (¬x̄ᵢ ∨ g)                  one
each original clause, with ¬xᵢ rewritten as x̄ᵢ, then ∨ ¬g        one
```

Any model that is not all-false has `g` true: if `g` were false, the guard
clauses `(¬xᵢ ∨ g)` and `(¬x̄ᵢ ∨ g)` would force every `xᵢ` and `x̄ᵢ` false, which
is the all-false model. With `g` true, the first two families make each pair
exactly one-hot — a total assignment — and the rewritten clauses say it
satisfies the original formula. Conversely a satisfying assignment yields such
a model. No clause has more than two negative literals and none has fewer than
one, so **every transition has at least one and at most two input places**.

Hence `PRESERVES(N, C)` is coNP-complete, already for unit arc weights and
capacities in `{0,1}`. Restricting the numbers does not help; the difficulty is
structural.

## What this settles, and what it does not

**Settled.** The open question is answered in the negative, conditionally:
there is no polynomial-time local condition — Weisfeiler-Leman colouring,
per-place rule, fixpoint, or anything else computable in polynomial time —
that is exact for multi-input transitions, unless P = NP. The non-claim
recorded in 0.1.0 (*"no claim that NO local capacity condition can repair the
multi-input case"*) is withdrawn and replaced by this conditional impossibility.

**Not settled.** This is a *written argument*, not a compiled one. Formalizing
coNP-completeness needs a formal model of computation, which is out of scope
here and is a different kind of artifact from the Lean theorems in this
dossier. What is machine checked is the **reduction**: that the constructed net
preserves exactly when the input CNF is unsatisfiable.

## Evidence

[`verification/hardness.py`](../verification/hardness.py) builds the net from a
CNF, hands it to this dossier's own `petri.py` semantics, and compares against
a brute-force satisfiability oracle.

| quantity | value |
|---|---|
| instances | 240 |
| agreements | **240** |
| disagreements | **0** |
| satisfiable instances | 171 |
| unsatisfiable instances | 69 |
| input places per transition | min 1, max 2 |

The reduction is also enumerated rather than only sampled. Over **every** CNF
on two variables with at most three clauses of width at most two — 164
formulas, 138 satisfiable and 26 not — there are no disagreements. A reduction
is a claim about all inputs, so a census that enumerates them cannot miss a
shape the sampler never produced; the random pass is what reaches the larger
instances.

Both outcomes being well populated is a gate, not a remark: a reduction that
only ever produced satisfiable instances would have tested one direction. So
is the input-place range, which is the whole point of the dichotomy — a
reduction that quietly used three input places would prove a weaker statement
than the one written here, and a reduction that used none would prove it in a
model this dossier does not admit.
