# Revision 0.8.0 — few multi-input transitions: fixed-parameter tractable

Revision 0.4.0 made preservation coNP-complete as soon as transitions may have
two input places, and revision 0.6.0 made it polynomial when none do. The
hardness construction uses **unboundedly many** multi-input transitions. This
revision fills in what happens between: for a fixed number `k` of them,
preservation is decided in polynomial time.

## The argument

A single-input transition is a dual-Horn clause: the markings at which it is
not capacity-enabled are closed under pointwise maximum
(`notCapEnabled_max_of_single`, the per-transition form of 0.6.0's closure).

A multi-input transition is blocked exactly when one of finitely many **unit
literals** holds (`blocked_by_some_literal`):

- some input place is below the transition's demand — an upper bound
  `m(q) ≤ pre(t,q) − 1`; or
- some place would overflow — a lower bound
  `m(q) ≥ cap(q) − post(t,q) + pre(t,q) + 1`.

Choose one literal for each multi-input transition. Upper and lower bounds are
both closed under maximum (`ub_max`, `lb_max`), so every branch is max-closed:
it has a greatest admissible solution, computed by 0.6.0's lowering started
from the chosen upper bounds. Lower bounds and ordinary enabledness are
upward-closed, so that one marking decides the branch. Exhaustiveness of the
branching — no bad marking falls between branches — is what
`blocked_by_some_literal` supplies.

At most `(#inputs + P)` literals per multi-input transition, so the work is
`(2P)^k` times a polynomial: fixed-parameter tractable in `k`.

## Not a new technique

This is branching on a **strong backdoor to Horn**, applied with
bounded-integer threshold literals instead of Boolean variables, and with
branches chosen per clause rather than per variable:

> Naomi Nishimura, Prabhakar Ragde, Stefan Szeider, *Detecting Backdoor Sets
> with Respect to Horn and Binary Clauses*.
> <https://www.ac.tuwien.ac.at/files/pub/nishimura-ragde-szeider-2004.pdf>

Their algorithms branch on literals of non-Horn clauses, and satisfiability is
fixed-parameter tractable given a small strong Horn backdoor. Both changes made
here preserve max-closure, which is all the classical argument uses. What this
revision records is the application, and the complexity picture it completes:

| multi-input transitions | complexity |
|---|---|
| none | polynomial (0.6.0) |
| a fixed number `k` | polynomial for each `k`; FPT in `k` (this revision) |
| unboundedly many, two inputs each | coNP-complete (0.4.0) |

## Compiled

| declaration | axioms |
|---|---|
| `upper_bound_blocks` | none |
| `ub_max`, `lb_max` | `propext` |
| `notCapEnabled_max_of_single`, `lower_bound_blocks` | `propext, Quot.sound` |
| `blocked_by_some_literal` | `propext, Classical.choice, Quot.sound` |

Not separately compiled: the lowering's termination with the capacities
replaced by chosen upper bounds. It is 0.7.0's argument verbatim, with a
smaller starting vector.

## Evidence

[`verification/backdoor.py`](../verification/backdoor.py), against the
dossier's own semantics over general nets with multi-input transitions allowed:

| quantity | value |
|---|---|
| systems | 145,953 |
| containing a multi-input transition | 114,048 |
| preserving / not preserving | 95,139 / 50,814 |
| **unsound / incomplete** | **0 / 0** |
| upper-bound literals dropped → wrong | 20,848 |
| lower-bound literals dropped → wrong | 8,074 |

The two ablations show each literal family is needed: without upper bounds the
branching misses transitions blocked by a short input, and without lower bounds
it misses transitions blocked by overflow.
