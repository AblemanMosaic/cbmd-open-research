# Revision 0.6.0 — one input place is the whole story

Revision 0.4.0 puts the complexity boundary at the number of **input** places
per transition. Its hardness construction uses only that ordinary enabledness
is a conjunction over inputs; outputs never enter it. So the polynomial side
should hold for any number of outputs — which revisions 0.3.0 and 0.5.0 do not
cover, since each of their transitions feeds at most one place.

It does, and for a reason that makes the previous two revisions' machinery
unnecessary.

## The whole case collapses to one marking

With one input place, *"m is capacity-dead"* is one clause per transition with
exactly **one negative literal** — `¬(w(t) ≤ m(input t))` — and one positive
literal per place that firing would overflow. Such a system is closed under
pointwise maximum.

> **Lemma (`capDead_max`).** If `m₁` and `m₂` are admissible and capacity-dead,
> so is their pointwise maximum.

*Proof.* Suppose `t` were capacity-enabled at `max(m₁, m₂)`. Its input place
attains the maximum at one of the two, say `m₁`. Then `t` is ordinarily enabled
at `m₁`: at the input place because the maximum is `m₁`'s, and elsewhere
because consumption is zero. And the overflow test passes for `m₁`: at the
input place the two markings agree, and elsewhere `m₁ ≤ max` with no
consumption to subtract. So `t` is capacity-enabled at `m₁`, which contradicts
its deadness. ∎

The single-input hypothesis is spent exactly once, in *"elsewhere consumption
is zero"*. No finiteness is used.

Hence there is a greatest capacity-dead admissible marking `M`, and because
ordinary enabledness is monotone in the marking,

> **Theorem.** `PRESERVES(N, C)` if and only if `M` is ordinarily dead.

Any capacity-dead admissible marking lies below `M`, so if any of them enables
something, `M` does.

## The algorithm, and its certificate

```
M := C
repeat: if some transition is capacity-enabled at M,
        lower its input place to one below that transition's weight
until stable
```

Each lowering is justified: for any capacity-dead `m` below the current vector
`u`, if `m` reached that transition's weight the transition would be
capacity-enabled at `m` too, because the overflow test is monotone in the
marking. That justification is the inductive predicate `Capped`, and
`capped_ge_of_bad` proves it sound — so the greatest-marking hypothesis is
**discharged**, not assumed.

This is the mirror image of revision 0.5.0. There the iteration raises levels
and the certificate is a lower bound (`Forced`); here it lowers and the
certificate is an upper bound (`Capped`). In both cases the procedure emits its
own justification and a checker validates it, rather than the proof trusting
that the procedure did the right thing.

## What this supersedes

Revision 0.5.0's **decision procedure** is superseded: seeding at each
transition and closing upward was `T` fixpoints where one downward fixpoint
suffices, and it was confined to single-output nets. Revision 0.5.0's
**characterization** — the level obstruction — stands, and remains the
statement of what a failure looks like; this revision replaces how it is
found and widens the class.

Revision 0.3.0's set-valued obstruction likewise remains the readable form of
the unit-weight case.

## Evidence

[`verification/single_input.py`](../verification/single_input.py) runs the
algorithm against this dossier's own semantics over nets with one input place
and **arbitrary** outputs and weights.

| quantity | value |
|---|---|
| systems | 31,905 |
| preserving / not preserving | 16,205 / 15,700 |
| **unsound** | **0** |
| **incomplete** | **0** |
| certificates that replay | **31,905** |
| certificates that fail to replay | **0** |
| dropping the overflow test → wrong verdicts | 15,700 |
| stopping after one pass → wrong verdicts | 784 |

The certificate rows are the ones that tie the Lean statement to the code: the
procedure records which transition it lowered at each step, and a separate
checker re-derives the whole sequence from the capacities, accepting a step
only when the transition really would be capacity-enabled at the vector
reached so far. That is the inductive `Capped` rule, checked rather than
assumed.

The second ablation is worth its row. Stopping after a single pass is wrong
only 784 times out of 31,905 — rare enough that a less adversarial test set
would have missed it, and exactly the sort of near-miss that makes an
iteration look unnecessary.
