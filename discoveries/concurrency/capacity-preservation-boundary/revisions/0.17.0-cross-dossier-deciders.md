# Revision 0.17.0 — two independently formalized deciders agree

A chip-firing system translates into a Petri net with one place and one
transition per vertex: the transition consumes `outdegree v` from its own place
and produces `mult v w` into the others. Each place has a single consumer, so
the net is conflict-free. Positive outdegree gives every transition an input
place. Under this translation the dossier's `Preserves` and the weighted
chip-firing dossier's `TerminalStable` say the same thing.

The two are formalized independently, in separate Lean projects, and each has
a decider proved correct: `decidePreservesFast` (0.15.0 here) and
`decideTerminalStable` (`CBMD-DYN-WEIGHTED-CAPACITY-001` 0.11.0).
`verification/cross_decider_bridge.py` has Lean run both on 300 random systems
from the weighted census generator:

| quantity | value |
|---|---|
| systems | 300 |
| the two Lean deciders agree | **300** |
| both agree with simulated transfer | **300** |
| transfer holds | 50 |

This checks the two formal models against each other. It is evidence that
neither formalization drifted from the shared mathematics. The translation
itself is checked on instances and not compiled.

One defect was caught on the way. The first run reported zero agreement
because both dossiers' bridge modules share a file name, and Python returned
the cached concurrency module for the weighted import, so the weighted Lean
file was built against the wrong library. The module is now loaded under a
distinct name. A bridge that silently runs the same code twice would have
reported perfect agreement. This one reported total disagreement, which made
the fault visible.
