# Revision 0.5.0 — weights, and why the obstruction has to carry levels

Revision 0.4.0 left one thing on the easy side of the dichotomy unfinished:
the polynomial case was established only for **unit** arc weights. This
extends it to arbitrary weights, and the extension is not cosmetic — the
unit-weight proof genuinely breaks.

## What breaks

Revision 0.3.0's obstruction is a **set** `S` of places held at capacity, and
its converse direction rests on a normalization: given a failing marking, raise
every occupied place to its capacity. With unit weights that is safe. With
weights it is not. Raising `m(a)` from `1` to `5` can make a transition that
takes `3` from `a` ordinarily enabled when it was not, and nothing need block
it. The witness stops being a witness.

So the obstruction has to carry **levels**, not membership.

## The condition

A weighted flow transition takes `w(t)` tokens from `src(t)` and, when it has a
destination, delivers `v(t)` of them. A level function `ℓ` is an obstruction at
capacity `C` when

1. `ℓ(q) ≤ C(q)` everywhere;
2. every drain `t` has `ℓ(src t) < w(t)` — a drain is never blocked, so a
   source at or above its weight could always fire;
3. every mover `t` with `w(t) ≤ ℓ(src t)` has `C(dst t) < ℓ(dst t) + v(t)`;
4. some `t` has `w(t) ≤ ℓ(src t)`.

> **Theorem.** `PRESERVES(N, C)` if and only if no obstruction exists.

With unit weights this collapses to revision 0.3.0: `ℓ(q) ∈ {0,1}` is
membership in `S`, clause 3 becomes *"the destination is full, or its capacity
is zero"*, and clause 2 becomes *"no drain takes from `S`"*.

## The algorithm, and why it is complete

Read clause 3 as an implication:

```
w(t) ≤ ℓ(src t)   ⟹   ℓ(dst t) ≥ C(dst t) − v(t) + 1
```

which is monotone in `ℓ`. That gives a decision procedure: for each transition
`t₀` in turn, seed `ℓ(src t₀) = w(t₀)`, close under the implication, and accept
if the closure stays inside the capacities and no drain is enabled at it.

Soundness is clause-by-clause. **Completeness** is the part worth proving: if
*any* failing marking `m` exists with `t₀` ordinarily enabled, then the least
closure seeded at `t₀` is itself an obstruction. The reason is that the least
closure lies below `m` — the seed does because `m` fires `t₀`, and each closure
step raises `ℓ(d)` only to `C(d) − v(t) + 1`, which `m(d)` already exceeds
because `m` is capacity-dead at `t`. Being below `m` gives clause 1 from
admissibility and clause 2 from `m`'s own drain-blocking. So testing the least
closure, once per transition, misses nothing.

Complexity: at most `T` closures, each raising levels monotonically inside the
box, so each terminates with the measure `Σ (C(q) − ℓ(q))` strictly decreasing.
Polynomial, which is the easy side of the 0.4.0 dichotomy, now for arbitrary
weights.

## What is compiled, and what is not

| declaration | axioms |
|---|---|
| `WFlow.obstructionOfFailure` | `propext` |
| `WFlow.least_closure_is_complete` | `propext` |
| `WFlow.obstruction_breaks` | `propext, Quot.sound` |
| `WFlow.preserves_iff_no_obstruction` | `propext, Quot.sound` |
| `WFlow.forced_le_of_bad` | `propext, Quot.sound` |
| `WFlow.justified_closure_is_complete` | `propext, Quot.sound` |

The leastness hypothesis is discharged rather than assumed. `Forced q n` is an
inductive predicate recording that *any* admissible capacity-dead marking
firing `t₀` must hold at least `n` at `q`; it is generated by the seed and by
one step per blocked mover, which is exactly what the iteration does.
`forced_le_of_bad` is the induction — previously prose — showing a forced level
really is a lower bound. `justified_closure_is_complete` then needs only that
each of `ℓ`'s entries is zero or forced, a condition the procedure can emit and
a checker can verify.

The guard `give t ≤ cap d` on the step is not decoration. A mover producing
more than its destination can hold is blocked whatever the destination holds,
so it forces nothing; without the guard, truncated subtraction would turn
`cap d − give t + 1` into `1` and claim a token that need not be there.

What remains prose: the **termination** of the closure iteration, from the
measure `Σ (C(q) − ℓ(q))` strictly decreasing.

**A hypothesis that was doing nothing, until it was.** The completeness lemma
was first stated with the assumption that the witnessing marking fires `t₀`.
Lean's linter flagged it unused, and it was — because leastness was being
assumed outright, and the seed already supplies clause 4. It was removed rather
than silenced. Once leastness is *derived* through `Forced`, that hypothesis
starts doing work again: it is the base case of `forced_le_of_bad`. The unused
binder was a symptom of the assumption that still needed discharging.

## Evidence

[`verification/weighted_flow.py`](../verification/weighted_flow.py) runs the
algorithm against this dossier's own `petri.py` semantics over six boxes.

| quantity | value |
|---|---|
| systems | 102,268 |
| preserving / not preserving | 53,493 / 48,775 |
| **unsound** | **0** |
| **incomplete** | **0** |
| drain check dropped → incomplete | 18,813 |
| capacity check dropped → incomplete | 33,801 |
| accepted closures carrying a valid `Forced` derivation | **48,775** |
| accepted closures **without** one | **0** |

The last two rows are what tie the proof to the procedure. The Lean
completeness lemma assumes each level is zero or forced; the script emits the
derivation the iteration used and re-checks it against the inductive rules
independently. Without that the Lean statement and the algorithm would be two
objects asserted to match.

**A redundancy the ablation found.** The first draft of the algorithm tested
the capacity box *inside* the closure loop **and** guarded the seed
`w(t₀) ≤ C(src t₀)` before starting. Ablating either changed nothing in any
box — which looked like two idle steps, and was actually one check written
twice: a closure step raises `ℓ(d)` to `C(d) − v(t) + 1 ≤ C(d)`, so the closure
can never leave the box, and only the seed can. One test after the closure is
enough. The ablation is kept, and now both remaining steps reject something.
