# Revision 0.7.0 — the last prose step compiled

Every revision on the proved side of this dossier has carried the same
caveat: *the termination of the iteration is a prose argument, not compiled.*
Revision 0.5.0 said it of the upward closure, 0.6.0 of the downward lowering.
That caveat is now gone for the single-input case, which is the one that
matters, since 0.6.0 showed it subsumes the others.

## What was missing

`preserves_iff_capped_ordDead` decides preservation from a marking `M` that is
admissible, capacity-dead, and whose every level is `Capped`. Nothing said
such an `M` exists. The procedure produces one, but "the procedure halts" was
the prose.

## What is compiled now

The argument is the obvious one and the work is in making it available without
Mathlib.

`sumBelow` sums a function over an initial segment of `Nat`; `total` sums a
marking over the places. `sumBelow_lt` — pointwise `≤` plus one strict drop
gives a strict drop in the sum — is proved by induction and depends on no
axioms at all. `total_lt` transports it to markings.

`lower N m t` drops the input place of `t` to one below that transition's own
weight. `lower_le` shows it never raises anything, and `lower_lt` shows it
strictly drops the input place, using that the transition was ordinarily
enabled there.

`exists_capped_capDead_aux` then runs the induction on an explicit bound: each
lowering strictly drops `total`, so `total m ≤ fuel` bounds the number of
lowerings. Starting from the capacities, whose every entry is `Capped` by
`Capped.init`, gives

```lean
theorem exists_capped_capDead (cap) (positive : ∀ t, 0 < N.pre t (N.input t)) :
    ∃ M, Admissible cap M ∧ N.CapDead cap M ∧ (∀ q, Capped N cap q (M q))
```

and composing with the decision theorem gives the capstone:

```lean
theorem preserves_decided_by_lowering (cap) (positive) :
    ∃ M, Admissible cap M ∧ N.CapDead cap M ∧ (N.Preserves cap ↔ N.OrdDead M)
```

One marking, reached from the capacities by lowering, decides preservation —
with nothing left to prose.

## The hypothesis that had been implicit

`positive : ∀ t, 0 < N.pre t (N.input t)` says each transition really does
consume from the place named as its input. The `SNet` structure only says
`pre` vanishes **off** the input place; it never said the input place is
genuinely an input. Without that, a transition consuming nothing anywhere is
always ordinarily enabled and the lowering has nothing to lower, so the
iteration need not reach a capacity-dead marking.

That hypothesis was present in the procedure all along — the census generators
never emit a zero-weight transition — but it was not written down. Compiling
the termination is what forced it into the open, which is the usual reason to
compile a step that "obviously" works.

transition is capacity-enabled.
