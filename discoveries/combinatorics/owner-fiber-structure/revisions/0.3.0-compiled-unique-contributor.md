# Revision 0.3.0 — the unique-contributor statement, compiled

Revision 0.2.0 checked the three parts of the claim by census and recorded two
degeneracy traps. The census tells you the statement did not fail on the box
that was sampled. This compiles the first part, so that for U1 the sampling
stops being the argument.

## What is proved, and from what

A universal type is a head word and a slot word, each of length `Q` over an
alphabet of size `r`. Two types lie in the same **orbit** when at every
coordinate the unordered pair `{head, slot}` agrees — each coordinate is either
left alone or swapped.

The development takes exactly two inputs, which are the two the census relies
on and nothing more:

* **`support_in_orbit`** — a nonzero source row forces the type into the
  target's orbit. In the reference model this is immediate: off the orbit the
  row is just the indicator at `y = u`, and `u` is in its own orbit.
* **`coherent`** — full-head coherence: a column's head word is its owner's
  head word.

From those:

| theorem | statement |
|---|---|
| `orbit_head_injective` | two orbit elements with the same head are equal |
| `unique_contributor` | a fixed target and owner admit at most one contributor |
| `contributor_eq_candidate` | and that contributor is the explicit `candidate` |

**Orbit-head injectivity is derived, not assumed.** The written claim lists it
among the premises; in this model it is a two-line case analysis. At a
coordinate where the target's head and slot differ, the head settles whether
that coordinate was swapped; where they agree, both branches give the same
letter in both positions, so there is nothing to settle. That is also the
content behind the claim's *activity* condition, isolated as
`active_head_determines_swap`.

`contributor_eq_candidate` is the part the census could only observe. It
measured that the candidate lookup predicted the contributing column in every
single-contributor fiber; now that is a theorem, so the agreement is not a
property of the sampled layouts.

## A lemma that was stated about the wrong thing

The first draft had a lemma claiming that a requested head missing at an
**active** coordinate names no orbit element. Lean's linter reported the
activity hypothesis unused — correctly, because the statement as written
(*every orbit element's head is one of the target's two letters*) is true at
every coordinate, active or not. It is now split: `orbit_head_mem` for the
general fact, and `active_head_determines_swap` for the one that genuinely
needs activity. The activity framing had been attached to the wrong statement.

## Checking that the theorem is about this model

A proof of the right statement about the wrong model is worth nothing, so the
verifier now measures the compiled theorem's own hypotheses and conclusion
against the layouts it generates:

| quantity | count |
|---|---|
| source rows examined | 1,536 |
| nonzero rows | 144 |
| nonzero rows **outside** the orbit | **0** |
| columns whose head is not their owner's head | **0** |
| distinct pairs within one orbit | 192 |
| such pairs sharing a head word | **0** |

The fifth row is the anti-vacuity control, and it took a correction to get
right. The first version counted *pairs of orbit elements sharing a head* and
required that count to be positive — demanding a witness of exactly what the
theorem forbids, so it could only ever fail. What makes injectivity non-vacuous
is that orbits contain distinct elements at all, which is what is counted now.
