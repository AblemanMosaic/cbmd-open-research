# Revision 0.7.0 — a native counterpart of one hypothesis, located

The compiled unique-contributor theorem (revision 0.3.0) takes two
hypotheses: `support_in_orbit` (a source row is nonzero only at a type in the
target's orbit) and `coherent` (a column's head word is its owner's).
`SOURCE_BOUND_COMPILED` was withdrawn (0.5.0) because both are hypotheses about
an abstract model rather than theorems about the declared source definitions.

A search of this repository's native proof package — prompted by a correction
in the amplitude-cost dossier, where a proof was wrongly said to be absent —
finds the amplitude half of the first hypothesis already compiled, against
Mathlib under Lean 4.34.1:

> `entry_eq_zero_of_not_inOrbit` — *the literal source entry has no support
> outside the swap orbit* —
> [`proofs/native/.../SqrtLog/ExecutableJointBCM1.lean`](../../../../proofs/native/lean/OAI/Algorithms/SubexponentialSAT/SqrtLog/ExecutableJointBCM1.lean),
> with `entry_support` and `joint_support` (no support beyond `R` mismatches)
> alongside.

## What this does and does not change

It changes where the remaining gap is. The integer amplitude's support
property is compiled for the native `LayoutNumerator.entry`. What is still
not compiled:
* the **row-level** statement — the source row is the indicator at `y = u`
  minus a multiple of the amplitude, so it follows from the amplitude
  statement, but that step is not compiled against the native definitions;
* the **binding** of this dossier's abstract `Typ`/`InOrbit` to the native
  `UniversalType`/`InOrbit`. The two projects use different toolchains
  (Lean 4.35.0 Mathlib-free here; Lean 4.34.1 with Mathlib there), so a
  compiled bridge needs one of them ported;
* **coherence**, which belongs to the packing, whose source definitions are not
  in the native package.

No status changes. `SOURCE_BOUND_COMPILED` stays withdrawn.
