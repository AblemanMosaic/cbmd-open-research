# Revision 0.6.0 — the claims against the packed reference, several blocks

Until now both parts of the claim were checked only against this dossier's own
finite model, which has a single covered block. The open obligation asks for
them to hold of the *packed* definitions: list order, first occurrence,
equal-type bucket ranks as blocks, the covered-block count, and the
missing-address, repeated-incidence, uncovered-target and exact-owner
branches.

The repository already carries a frozen packed reference with exactly those
semantics:
`discoveries/algorithms/reference-amplitude-cost-model/verification/reference-model/src/owner_sum.py`.
`verification/packed_reference.py` checks the claims against it directly, on
layouts with two or three blocks, duplicated head words, deliberately
repeated pairs, and leftover incidences beyond the covered count.

Every packed branch is exercised, and both controls fail as they must: the
block structure is load-bearing, and so is coherence.

**One reading had to be fixed.** U2 counts `(block, orbit-class)` pairs. An
uncovered target belongs to no block. Its only possible contributor is itself,
on the diagonal, so it is counted as a class of its own. Under that reading the
bound holds everywhere.

## What this is not

hash — not a compiled correspondence to the archive's packed Lean definitions.
`SOURCE_BOUND_COMPILED` stays withdrawn. The unresolved item *multi-block
packing is not modelled* becomes *multi-block packing is censused, not
compiled*.
