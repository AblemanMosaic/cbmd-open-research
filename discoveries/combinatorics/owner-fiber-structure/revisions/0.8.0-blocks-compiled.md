# Revision 0.8.0 — multi-block packing, compiled

Revision 0.6.0 checked both claims against the packed reference on multi-block
layouts by census. `Blocks.lean` now compiles them with blocks, and derives
the packing invariant from the definition of a block.

| declaration | content |
|---|---|
| `rankAt` | an incidence's block: the number of earlier incidences with the same label, in list order |
| `rank_injective` | two positions with the same label have different ranks, so within a block each label occurs at most once |
| `unique_contributor_blocks` | for a target in block `b` and a fixed owner, at most one incidence of block `b` contributes |
| `contributor_class_injective_blocks` | targets in the same block and orbit class share their contributor, so per owner the contributors are at most the distinct `(block, orbit-class)` pairs |

The hypotheses are those of revision 0.3.0, `support_in_orbit` and
`coherent`, plus injective label decoding. The packing invariant is not
assumed: `rank_injective` proves it from the rank definition.

## Bridge

`rankAt` is the packed reference's block. `verification/packed_reference.py`
now checks this on every incidence of every generated layout: the position of
an incidence in its label's bucket equals the number of earlier incidences
with that label. Gate `block_is_compiled_rank`, 0 mismatches.

## Standing

The unresolved item "multi-block packing is censused, not compiled" is
retired. What remains is the binding to the archive's packed source
definitions: the row-level support step, the model binding, and coherence
(revision 0.7.0). `SOURCE_BOUND_COMPILED` stays withdrawn.
